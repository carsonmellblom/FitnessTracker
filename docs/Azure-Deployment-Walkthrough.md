# Azure Deployment Walkthrough (Secure VNet - West US)

This guide details the manual steps to set up your Azure environment using a **Virtual Network** in **West US**.

**Note for PowerShell Users:** These commands use the backtick (`` ` ``) for line continuation. If you are using Git Bash or WSL, replace them with backslashes (`\`).

## Prerequisites
- **Delete existing resources**: Run `az group delete --name FitnessTrackerRG` to clear the slate.

## 1. Create Resource Group (West US)
```powershell
az group create --name FitnessTrackerRG --location westus
```

## 2. Register Providers
```powershell
az provider register --namespace Microsoft.ContainerRegistry --wait
az provider register -n Microsoft.OperationalInsights --wait
az provider register -n Microsoft.Web --wait
az provider register --namespace Microsoft.DBforPostgreSQL --wait
az provider register --namespace Microsoft.App --wait
az provider register --namespace Microsoft.Network --wait
```

## 3. Create Network Infrastructure

### A. Create Virtual Network (VNet)
**What is `10.0.0.0/16`?**
This is CIDR notation. It defines the size of your network.
- `10.0.0.0` is the starting IP address.
- `/16` means the first 16 bits are fixed (10.0), and the remaining 16 bits vary.
- Result: **65,536** available IP addresses (10.0.0.0 to 10.0.255.255).
- We carve this big block up into smaller "subnets" for specific apps.

```powershell
az network vnet create `
  --name fitness-vnet `
  --resource-group FitnessTrackerRG `
  --location westus `
  --address-prefixes 10.0.0.0/16
```

### B. Create Subnets
**1. App Subnet (Azure Container Apps)**
```powershell
az network vnet subnet create `
  --name snet-apps `
  --resource-group FitnessTrackerRG `
  --vnet-name fitness-vnet `
  --address-prefixes 10.0.0.0/23 `
  --delegations Microsoft.App/environments
```

**2. Database Subnet (PostgreSQL)**
```powershell
az network vnet subnet create `
  --name snet-db `
  --resource-group FitnessTrackerRG `
  --vnet-name fitness-vnet `
  --address-prefixes 10.0.2.0/24 `
  --delegations Microsoft.DBforPostgreSQL/flexibleServers
```

### C. Create Private DNS Zone
```powershell
az network private-dns zone create `
  --resource-group FitnessTrackerRG `
  --name fitness.private.postgres.database.azure.com

az network private-dns link vnet create `
  --resource-group FitnessTrackerRG `
  --zone-name fitness.private.postgres.database.azure.com `
  --name fitness-dns-link `
  --virtual-network fitness-vnet `
  --registration-enabled false
```

## 8. Deploy Backend Containers (Initial Setup)
**Run this AFTER your GitHub Action has built and pushed the images to ACR.**

> [!IMPORTANT]
> The commands below incorporate all fixes discovered during deployment troubleshooting. Follow them exactly to avoid common pitfalls.

### A. RabbitMQ Message Broker
```powershell
# Create RabbitMQ with TCP Ingress
az containerapp create `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --environment fitness-env `
  --image rabbitmq:3-management `
  --target-port 5672 `
  --exposed-port 5672 `
  --ingress internal `
  --transport tcp `
  --min-replicas 1 `
  --max-replicas 1 `
  --env-vars "RABBITMQ_DEFAULT_USER=secretuser" "RABBITMQ_DEFAULT_PASS=secretpass"
```

**Environment Variables Explained:**
- `RABBITMQ_DEFAULT_USER`: Admin username for RabbitMQ (replace `secretuser` with your chosen username)
- `RABBITMQ_DEFAULT_PASS`: Admin password for RabbitMQ (replace `secretpass` with a strong password)

**Critical Flags:**
- `--exposed-port 5672`: **REQUIRED** - Without this, Azure assigns a random port and connections fail
- `--transport tcp`: Enables TCP protocol (required for AMQP)
- `--ingress internal`: Only accessible within the Container Apps environment

### B. Get RabbitMQ Internal FQDN
```powershell
# Get the full internal hostname for RabbitMQ
$rabbitFqdn = az containerapp show `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --query "properties.configuration.ingress.fqdn" `
  --output tsv

Write-Host "RabbitMQ FQDN: $rabbitFqdn"
# Example output: fitness-rabbitmq.internal.bravegrass-9195be51.westus.azurecontainerapps.io
```

> [!WARNING]
> Using the short hostname `fitness-rabbitmq` often fails due to DNS resolution issues. **Always use the full FQDN** returned above.

### C. .NET API App
```powershell
az containerapp create `
  --name fitness-api `
  --resource-group FitnessTrackerRG `
  --environment fitness-env `
  --image fitnesstrackerappacr.azurecr.io/fitness-tracker-api:latest `
  --target-port 8080 `
  --ingress external `
  --registry-server fitnesstrackerappacr.azurecr.io `
  --registry-username <ACR_USERNAME> `
  --registry-password <ACR_PASSWORD> `
  --min-replicas 1 `
  --max-replicas 1 `
  --env-vars `
    "ConnectionStrings__DefaultConnection=Host=fitness-db.postgres.database.azure.com;Database=fitnessTracker;Username=myadmin;Password=<DB_PASSWORD>" `
    "RabbitMQ__Host=$rabbitFqdn" `
    "RabbitMQ__Username=secretuser" `
    "RabbitMQ__Password=secretpass" `
    "AllowedOrigins__0=https://your-static-web-app.azurestaticapps.net" `
    "CookieSettings__SameSiteMode=None" `
    "CookieSettings__SecureCookies=true" `
    "AzureStorage__ConnectionString=<STORAGE_CONNECTION_STRING>" `
    "AzureStorage__ContainerName=progress-photos"
```

**Environment Variables Explained:**
- `ConnectionStrings__DefaultConnection`: PostgreSQL connection string
  - **Host**: Use `fitness-db.postgres.database.azure.com` (public FQDN) - works from within VNet
  - **Database**: Must match exactly: `fitnessTracker` (case-sensitive!)
  - **Username/Password**: Your PostgreSQL admin credentials
- `RabbitMQ__Host`: **Full FQDN** from step B (e.g., `fitness-rabbitmq.internal....azurecontainerapps.io`)
- `RabbitMQ__Username`: Must match `RABBITMQ_DEFAULT_USER` from step A
- `RabbitMQ__Password`: Must match `RABBITMQ_DEFAULT_PASS` from step A
- `AllowedOrigins__0`: Your Static Web App URL (for CORS) - get from Azure portal
- `CookieSettings__SameSiteMode=None`: **Required** for cross-domain authentication cookies
- `CookieSettings__SecureCookies=true`: **Required** when using HTTPS
- `AzureStorage__ConnectionString`: Connection string from step 6.C
- `AzureStorage__ContainerName`: Blob container name (`progress-photos`)

> [!CAUTION]
> Do NOT use `localhost` in the Database Host. Do NOT use the private DNS name (`fitness-db.fitness.private...`) as it often fails to resolve.

### D. Python Photo Processor
```powershell
az containerapp create `
  --name fitness-photo-processor `
  --resource-group FitnessTrackerRG `
  --environment fitness-env `
  --image fitnesstrackerappacr.azurecr.io/photo-processor:latest `
  --registry-server fitnesstrackerappacr.azurecr.io `
  --registry-username <ACR_USERNAME> `
  --registry-password <ACR_PASSWORD> `
  --min-replicas 1 `
  --max-replicas 1 `
  --env-vars `
    "RABBITMQ_HOST=$rabbitFqdn" `
    "RABBITMQ_USER=secretuser" `
    "RABBITMQ_PASSWORD=secretpass" `
    "DB_HOST=fitness-db.postgres.database.azure.com" `
    "DB_NAME=fitnessTracker" `
    "DB_USER=myadmin" `
    "DB_PASSWORD=<DB_PASSWORD>" `
    "AZURE_STORAGE_CONNECTION_STRING=<STORAGE_CONNECTION_STRING>" `
    "AZURE_STORAGE_CONTAINER_NAME=progress-photos"
```

**Environment Variables Explained:**
- `RABBITMQ_HOST`: **Full FQDN** from step B 
- `RABBITMQ_USER`: Must match `RABBITMQ_DEFAULT_USER` from step A
- `RABBITMQ_PASSWORD`: **NOT** `RABBITMQ_PASS` - the Python config file expects `RABBITMQ_PASSWORD`
- `DB_HOST`: Use public FQDN `fitness-db.postgres.database.azure.com`
- `DB_NAME`: Must be exactly `fitnessTracker` (case-sensitive, matches database name)
- `DB_USER`: PostgreSQL username
- `DB_PASSWORD`: PostgreSQL password
- `AZURE_STORAGE_CONNECTION_STRING`: Connection string from step 6.C  
- `AZURE_STORAGE_CONTAINER_NAME`: Blob container name (`progress-photos`)

> [!IMPORTANT]
> Notice the processor uses `RABBITMQ_PASSWORD` while the API uses `RabbitMQ__Password`. This is because:
> - **Python** reads `RABBITMQ_PASSWORD` (defined in `config.py`)
> - **.NET** reads `RabbitMQ__Password` (double-underscore configuration convention)
> 
> **Same applies to Azure Storage:**
> - **Python**: `AZURE_STORAGE_CONNECTION_STRING` (underscores)
> - **.NET**: `AzureStorage__ConnectionString` (double-underscore)

### E. Create RabbitMQ User with Permissions
After creating the containers, you must create a proper RabbitMQ user with queue permissions:

```powershell
# Create user
az containerapp exec `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --command "rabbitmqctl add_user secretuser secretpass"

# Make user administrator
az containerapp exec `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --command "rabbitmqctl set_user_tags secretuser administrator"

# Grant full permissions on default vhost
az containerapp exec `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --command "rabbitmqctl set_permissions -p / secretuser .* .* .*"
```

**Why This is Necessary:**
- RabbitMQ environment variables (`RABBITMQ_DEFAULT_USER/PASS`) only work on **first container creation**
- If you recreate the container or change credentials later, you must manually update the user via `rabbitmqctl`
- The `.* .* .*` grants configure, write, and read permissions on all resources

### Issue 1: Database Connection Failures

**Symptom:**
```
connection to server at "fitness-db.fitness.private.postgres.database.azure.com" 
(10.0.2.4), port 5432 failed: Name or service not known
```

**Root Cause:**
The private DNS zone name (`fitness-db.fitness.private.postgres.database.azure.com`) doesn't always resolve correctly from Container Apps.

**Solution:**
Use the **public FQDN** which still works within the VNet:

```powershell
# API
az containerapp update `
  --name fitness-api `
  --resource-group FitnessTrackerRG `
  --set-env-vars "ConnectionStrings__DefaultConnection=Host=fitness-db.postgres.database.azure.com;Database=fitnessTracker;Username=myadmin;Password=<PASSWORD>"

# Processor
az containerapp update `
  --name fitness-photo-processor `
  --resource-group FitnessTrackerRG `
  --set-env-vars DB_HOST=fitness-db.postgres.database.azure.com
```

**Key Points:**
- Use `fitness-db.postgres.database.azure.com` NOT `fitness-db.fitness.private...`
- Database name is `fitnessTracker` (case-sensitive!)
- Both API and Processor need this fix

### Issue 2: Backend Not Listening on Correct Port

**Symptom:**
```
Container ready but returning 502 Bad Gateway
```

**Root Cause:**
`.NET` application was hardcoded to listen on `localhost:5067` in `Program.cs`.

**Solution:**
Remove any `UseUrls()` calls that force localhost:

```csharp
// REMOVE THIS LINE if present in Program.cs
builder.WebHost.UseUrls("http://localhost:5067"); 
```

**Why This Works:**
- Container Apps Ingress Controller expects the app to listen on `0.0.0.0:8080`
- Hardcoding `localhost` prevents external traffic from reaching the app
- The default behavior (no `UseUrls`) correctly binds to all interfaces on port 8080

### Issue 3: Frontend Shows "Failed to Fetch"

**Symptom:**
Frontend loads but all API calls fail with network errors.

**Root Cause:**
Frontend doesn't know the deployed API URL (still using localhost).

**Solution:**

**Step 1:** Create `.env.production` file:

```bash
# src/FitnessTracker.Web/.env.production
```

```javascript
const API_BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:5067/api/v1';

// AFTER (GOOD):
const API_BASE_URL = import.meta.env.VITE_API_URL;
```

**Step 3:** Redeploy frontend

### Issue 4: Login Works But All POST Requests Return 401

**Symptom:**
- Login succeeds and returns user data
- Subsequent authenticated POST requests fail with `401 Unauthorized`
- GET requests work fine

**Root Cause:**
Browsers block cross-domain cookies by default. Frontend (`azurestaticapps.net`) and Backend (`azurecontainerapps.io`) are different domains.

**Solution:**
Configure cookies with `SameSite=None` and `Secure=True`:

```powershell
az containerapp update `
  --name fitness-api `
  --resource-group FitnessTrackerRG `
  --set-env-vars `
    CookieSettings__SameSiteMode=None `
    CookieSettings__SecureCookies=true `
    "AllowedOrigins__0=https://your-app.azurestaticapps.net"
```

**Environment Variables Explained:**
- `CookieSettings__SameSiteMode=None`: Allows cookies to be sent cross-domain
- `CookieSettings__SecureCookies=true`: Required when `SameSite=None` (HTTPS only)
- `AllowedOrigins__0`: CORS configuration to allow frontend domain

**Backend Code Requirements:**
Your `AuthController.cs` must read these settings:
```csharp
private void SetAuthCookies(string accessToken, string refreshToken)
{
    var secureCookies = _configuration.GetValue<bool>("CookieSettings:SecureCookies");
    var sameSiteModeString = _configuration.GetValue<string>("CookieSettings:SameSiteMode") ?? "Lax";
    var sameSiteMode = Enum.Parse<SameSiteMode>(sameSiteModeString);
    
    var cookieOptions = new CookieOptions
    {
        HttpOnly = true,
        Secure = secureCookies,
        SameSite = sameSiteMode,
        // ... rest of cookie settings
    };
}
```

### Issue 8: RabbitMQ Queue Permission Denied

**Symptom:**
```
pika.exceptions.ChannelClosedByBroker: (403, "ACCESS_REFUSED - configure 
access to queue 'photo-processing' in vhost '/' refused for user 'myuser'")
```

**Root Cause:**
User exists but doesn't have permissions to create queues.

**Solution:**
Grant full permissions on the default vhost (`/`):

```powershell
az containerapp exec `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --command "rabbitmqctl set_permissions -p / myuser .* .* .*"
```

**Permission Format Explained:**
- `rabbitmqctl set_permissions -p VHOST USERNAME CONFIGURE WRITE READ`
- `.*` = regex matching all resources
- Three `.*` = full configure, write, and read permissions

If the queue already exists with wrong ownership:
```powershell
# Delete the queue
az containerapp exec `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --command "rabbitmqctl delete_queue photo-processing"

# Restart processor to recreate queue with correct user
az containerapp revision restart `
  --name fitness-photo-processor `
  --resource-group FitnessTrackerRG `
  --revision $(az containerapp revision list --name fitness-photo-processor --resource-group FitnessTrackerRG --query "[0].name" -o tsv)
```

### Issue 9: RabbitMQ TCP Ingress Not Working

**Symptom:**
Connection timeouts to RabbitMQ despite user/password being correct.

**Root Cause:**
RabbitMQ container created without proper TCP ingress configuration.

**Solution:**

**If Ingress is NOT Enabled:**
```powershell
az containerapp ingress enable `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --type internal `
  --target-port 5672 `
  --exposed-port 5672 `
  --transport tcp
```

**If Ingress Exists But Broken:**
```powershell
# Disable
az containerapp ingress disable `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG

# Re-enable with correct settings
az containerapp ingress enable `
  --name fitness-rabbitmq `
  --resource-group FitnessTrackerRG `
  --type internal `
  --target-port 5672 `
  --exposed-port 5672 `
  --transport tcp
```

**Critical Flags:**
- `--exposed-port 5672`: **MUST** be specified or Azure assigns a random port
- `--transport tcp`: Required for AMQP protocol
- `--type internal`: Keeps RabbitMQ private to the environment
